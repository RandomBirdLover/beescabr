# `data/analysis/` — native-bee analysis catalog

This folder holds the **outputs of every analysis run** on the CABR native-bee
data. Each run is generated by a script in `scripts/analysis/` and catalogued
below. Everything here is generated — don't edit by hand; re-run the script to
refresh. This README is the index: as tests are added, add a registry row + a
detail section (see *Adding a new run* at the bottom).

Full feasibility notes, method detail, and the concept/input fixes behind the
planned runs live in **`analysis_roadmap.md`** (this folder) (the stakeholder-question
triage). This registry is the short index; the roadmap is the reasoning.

## Categories

Each run is tagged with one category. Extend this list as new questions come up.

| slug | category | the question it answers |
|---|---|---|
| `completeness` | Sampling completeness & accumulation | Have we surveyed enough — how many taxa are we still missing? |
| `coverage` | Coverage, gaps & resolution | Who/what/where are we catching vs missing, and at what taxonomic rank? |
| `richness/diversity` | Diversity indices | How diverse/even is each transect, year, or method — and where in the park? |
| `phenology` | Temporal & phenology | How do activity, effort, and flowering change through the season and years? |
| `interactions` | Plant–bee interactions | Which bees use which plants — what does the visitation network look like? |
| `composition` | Community composition & ordination | Do the assemblages differ between transects / years / methods? |
| `richness/rarefaction` | Effort-controlled diversity | Comparing diversity fairly by standardizing sampling effort (vegan + iNEXT). |
| `coverage/bee_bounties` | Method-gap task lists | Which bees to collect (voucher) or photograph, and where/when/on what to find them. |
| `reference/nps_summary` | NPS descriptive summaries | Plain counts for the data-focused NPS report — no interpretation. |

**Status key:** ✅ done · 🔬 in progress · 📋 planned · ⛔ blocked (waiting on an input)

scopes are **CABR only** (not PL/SD).

## Running the analyses (in isolation)

**These scripts are independent of each other.** Each reads only the pipeline's
cleaned outputs (the shared inputs above) + `scripts/config.R` — never another
analysis script's output. So there is **no dependency chain between them**; the only
prerequisite is that the pipeline has produced the cleaned tables.

1. **Prerequisite (once):** run the pipeline so the cleaned tables + checklist +
   resolved `plant_genus` columns exist — `Rscript scripts/run_data_cleaning_pipeline.R` (or
   confirm the five shared-input files above are present and current).
2. **Then run any analysis script, in any order**, from the **repo root**:

   ```
   Rscript scripts/analysis/genera_and_species_accumulation.R   # Q5   vegan, dplyr, stringr
   Rscript scripts/analysis/coverage_cabr_vs_holway.R           # Q10  dplyr, stringr
   Rscript scripts/analysis/coverage_method_venn.R              # Q1   dplyr, stringr
   Rscript scripts/analysis/coverage_yield_by_group.R           # Q11  dplyr, stringr, ggplot2
   Rscript scripts/analysis/coverage_offtransect.R              # Q6   dplyr, stringr, ggplot2
   Rscript scripts/analysis/coverage_id_targets.R               # Q7   dplyr, stringr, ggplot2
   Rscript scripts/analysis/interactions_top_plants.R           # Q3   dplyr, stringr
   Rscript scripts/analysis/interactions_network.R              # Q4   dplyr, stringr, igraph, ggplot2, vegan (+ optional bipartite)
   Rscript scripts/analysis/interactions_genus_species_webs.R   # Q4+  dplyr, stringr, ggplot2  (per-genus species webs)
   Rscript scripts/analysis/phenology_activity.R                # Q12  dplyr, stringr, ggplot2, ggridges
   Rscript scripts/analysis/phenology_effort.R                  # Q13  dplyr, stringr, ggplot2
   Rscript scripts/analysis/diversity_indices.R                 # Q8   dplyr, stringr, vegan, ggplot2
   Rscript scripts/analysis/spatial_richness_map.R              # Q8   sf, dplyr, stringr, vegan, ggplot2  (all-records map)
   Rscript scripts/analysis/rarefaction_vegan.R                 # rarefaction  dplyr, stringr, vegan, ggplot2
   Rscript scripts/analysis/rarefaction_inext.R                 # rarefaction  dplyr, stringr, iNEXT, ggplot2  (needs internet for iNEXT)
   Rscript scripts/analysis/bee_bounties.R                      # bounties     dplyr, stringr, ggplot2
   Rscript scripts/analysis/nps_summary_tables.R                # NPS summary  dplyr, stringr
   ```

   Every script writes into its **per-category subfolder** under `data/analysis/`
   (`richness/accumulation/`, `coverage/method_comparison/`, `interactions/networks/`, `phenology/`) and prints a one-line
   summary. The order above is just a sensible reading order (coverage → interactions);
   swap freely. Extra packages self-install on first run. If you only changed one
   question, just re-run that one script.

## Folder layout & statistical tests

Outputs are organized into subfolders by category; each subfolder holds that
category's figures + CSVs **and a `*_statistics.docx`** documenting the methods,
statistical tests, results, and caveats.

| subfolder | analyses | statistical test(s) | stats doc |
|---|---|---|---|
| `richness/accumulation/` | Q5 | Chao2 richness estimators + SE; permutation CI bands (estimation, no p-value) | `accumulation_statistics.docx` |
| `coverage/` | Q1, Q2, Q6, Q7, Q10, Q11 | **χ² test** of taxonomic resolution × method (χ²=280, p<1e-16); Venn, not-on-Holway, group-yield (Q11), off-transect (Q6) & target-ID list (Q7) are descriptive | `coverage_statistics.docx` |
| `interactions/` | Q3, Q4 | **NODF nestedness** vs null (`vegan::oecosimu`, quasiswap); **H2′ specialization** vs fixed-marginal null (`r2dtable`, self-contained — both p=0.001); **per-genus within-genus H2′** (species→plant webs, 11 genera); top-plants descriptive | `interactions_statistics.docx` |
| `phenology/` | Q12, Q13 | **Rayleigh test** of circular uniformity per taxon (only taxa with ≥10 records get a curve/test); effort calendar (Q13) descriptive | `phenology_statistics.docx` |
| `richness/diversity/` | Q8 | **PERMANOVA** of composition × transect + year (`vegan::adonis2`, Bray–Curtis); alpha indices + rank-abundance descriptive; **spatial richness map** (all-records, `sf`, w/ effort-controlled rarefied surface) | `diversity_statistics.docx` |
| `richness/rarefaction/` | effort control | **rarefaction** to standardize effort — vegan (rarefy-to-lowest) + iNEXT (Hill q0/q1/q2, size- and coverage-based); estimation with CIs, no p-value | `README.md` (method guide) |
| `coverage/bee_bounties/` | method gaps | descriptive gap lists (in one method, not the other) + where/when/on-what context; no test | — |
| `reference/nps_summary/` | descriptive | plain counts only (participants, bees, plants, methods) — deliberately no tests | — |

Headline stats results: ID resolution depends strongly on method (nets 81% vs photos
53% species-level, p<1e-16); the plant–bee networks are **not** significantly nested
(NODF not significant at either rank) but **are** significantly specialized (H2′=0.29
genus, 0.43 species, both p=0.001 vs a fixed-marginal null); nearly every taxon is
significantly seasonal (Rayleigh p<0.05); bee composition differs by transect (R²=0.23)
and year (R²=0.50), both p=0.001. The `.docx` in each folder has the full write-up.

## ✅ Genera & species accumulation, per transect — `completeness`  (Q5)

**Script:** `scripts/analysis/genera_and_species_accumulation.R`
**Run:** `Rscript scripts/analysis/genera_and_species_accumulation.R` (needs `vegan`, `dplyr`, `stringr`)

*As we run more surveys on a transect, how fast do we keep turning up new bee
taxa, and how close are we to having found them all?* — at two ranks, one curve
per transect.

- **x-axis = number of surveys**, from `master_per_survey_info.csv`. A multi-transect
  day counts as one survey for each transect it covered. Zero-catch surveys still
  count as effort (they flatten the curve).
- **Lines = transects** (BST, UPMON, TP, OT); **bands = 95% CI** from
  `vegan::specaccum(method = "random")`, 200 permutations, seeded.
- **Richness estimate = Chao2** (incidence, `vegan::specpool()`): from taxa seen in
  exactly one vs two surveys, estimate how many were missed.

**Outputs**

- `accumulation_species_by_transect.png` — cumulative species vs surveys.
- `accumulation_genera_by_transect.png` — cumulative genera vs surveys.
- `accumulation_species_by_method.png`, `accumulation_genera_by_method.png` — the same curves grouped by **method** (lethal net vs non-lethal photo), pooled across transects.
- `accumulation_species_by_transect_method.png`, `accumulation_genera_by_transect_method.png` — **2×2 facet**, one panel per transect, each showing lethal vs non-lethal.
- `transect_accumulation_summary.csv` — per-transect effort + observed & Chao2 richness. Columns:

  | column | meaning |
  |---|---|
  | `transect` | transect code |
  | `n_surveys` | surveys on that transect (incl. zero-catch) |
  | `surveys_lethal` / `surveys_nonlethal` | method split of those surveys |
  | `species_observed` | distinct species recorded |
  | `species_chao2` / `species_chao2_se` | Chao2 estimate of true species richness + SE |
  | `species_pct_complete` | `100 × species_observed / species_chao2` |
  | `genera_observed` | distinct genera recorded |
  | `genera_chao2` / `genera_chao2_se` | Chao2 estimate of true genus richness + SE |
  | `genera_pct_complete` | `100 × genera_observed / genera_chao2` |

**What the ± SE means:** the Chao2 number is an *estimate* of the true richness, and the
standard error (SE) says how precise that estimate is — the true value is roughly 95%
likely to fall within ±2 SE of it. A small SE means a tight, trustworthy estimate; a
large SE (e.g. OT's 78 ± 43) means the estimate is rough and really says "sample more
here," not "there are exactly 78 species."

**Results (last run)**

| transect | surveys | species (obs → Chao2, % complete) | genera (obs → Chao2, % complete) |
|---|---|---|---|
| BST | 153 | 36 → 50.3 (72%) | 24 → 28.1 (85%) |
| UPMON | 152 | 41 → 46.0 (89%) | 23 → 23.2 (99%) |
| TP | 252 | 36 → 42.1 (86%) | 23 → 23.0 (100%) |
| OT | 47 | 30 → 78.0 (39%) | 20 → 22.0 (91%) |

Genus inventories are essentially complete everywhere (85–100%); species still
climbing. UPMON is richest/best-sampled (~89%); TP has the most surveys but adds
few new species. **OT is undersampled** — 47 surveys, many one-off species, so
Chao2 (78 ± 43, ~39%) is a "needs more effort" flag, not a precise target.

## ✅ Plant–bee visitation networks — `interactions/networks`  (Q4)

**Script:** `scripts/analysis/interactions_network.R`
**Run:** `Rscript scripts/analysis/interactions_network.R` (needs `dplyr`, `stringr`, `igraph`, `vegan`, `ggplot2`)

*Which flowers do which bees visit, and which plants do the rarer bees depend on?*
Built from the resolved `plant_genus` column, both methods pooled, at two ranks.

- **Two networks** (like accumulation): plant genus × **bee genus** (every
  genus-resolved record; 84×31) and plant genus × **bee species** (species-level; 69×74).
- Node convention: plant genus = rows, bee = columns; cells count co-occurrence records.
- **Specialist / rare** read is species-rank only: specialist = visits ≤2 plant
  genera; lesser-seen = bottom-quartile relative frequency.

**Outputs**

- `interactions_matrix_genus.csv`, `interactions_matrix_species.csv` — full incidence matrices.
- `interactions_heatmap_genus.png`, `interactions_heatmap_species.png` — visitation intensity (top-30 plant genera).
- `interactions_bee_genus_network.png` — igraph one-mode projection: bee genera linked by shared plant genera (generalist hub vs specialist rim).
- `interactions_bee_specialization.csv` — per bee species: plant-genera breadth, main forage, `specialist` / `lesser_seen` flags.
- `interactions_network_stats.csv` — network-level metrics + significance: connectance, **NODF** (nestedness) vs quasiswap null with p, **H2′** (specialization) vs `r2dtable` null with p — for both the genus and species networks.
- `interactions_web_genus.png`, `interactions_web_species.png` — dependency-free bipartite web (plant genera on the bottom, bees on top, links = visits).

**Results (last run):** 9,444 interaction records. Broadest foragers = *Lasioglossum*
(65 plant genera), *Ceratina* (42), *Augochlorella* (41), *Bombus* (40); top plants =
Encelia, Stephanomeria, Isocoma, Eriogonum, Deinandra. **43 of 74 bee species visit
≤2 plant genera** (candidate specialists) — e.g. *Diadasia ochracea*→Malacothamnus,
*Centris rhodopus*→Stephanomeria, *Colletes ochraceus*→Isocoma. Whole-network
specialization is significant at both ranks (**H2′ = 0.29 genus, 0.43 species, p = 0.001**),
though the networks are **not** nested (NODF n.s.).

### What NODF and H2′ mean (in bee terms)

Two different questions about the same network:

**NODF — nestedness.** Rank the bees from broadest generalist to narrowest specialist
and the plants from most- to least-visited. The network is *nested* if the specialist
bees feed only on a **subset of the same plants the generalists use** — nobody has a
private plant; the picky bees just eat a smaller slice of the popular menu (e.g.
*Perdita* using only plants that *Bombus* also visits heavily). The test asks: **more
nested than random bee–plant pairings?** Here the answer is **no** — so CABR's
specialists are *not* merely eating subsets of the generalists' plants; several have
their own host plants the generalists largely ignore. Tested one-sided ("more nested
than chance"), matching H2′'s tail.

**H2′ — specialization.** The complementary question: do the bees **divide up the
flowers** (each favouring its own plants) or all pile onto the same blooms? H2′ = 0
means every bee visits plants just in proportion to how common they are (no
preferences); H2′ = 1 means perfect partitioning (each bee on its own exclusive
plants). CABR is **significantly specialized** (0.29 genus / 0.43 species) — the bees
really do partition the floral resources — with *Perdita* and *Diadasia* as tight host
specialists and *Bombus* / *Agapostemon* as generalists.

**Together:** the CABR bees **specialize on and partition their host plants** (high
H2′) rather than forming a nested "everyone-shares-the-common-flowers" structure
(non-significant NODF) — a real host-specialization signal, not a contradiction.

### Zoom-in: per-genus species → plant webs

**Script:** `scripts/analysis/interactions_genus_species_webs.R` (needs `dplyr`, `stringr`, `ggplot2`)

*Within a bee genus, do its species split up the plant genera (niche partitioning) or
pile onto the same ones?* For each bee genus with ≥2 species resolved and ≥20 visitation
records (**11 genera**; Anthidium/Colletes/Megachile/Melissodes too sparse), a bipartite
web links that genus's species to plant genera, plus a **within-genus H2′** (0 = species
overlap on plants, 1 = each on its own) tested vs the `r2dtable` null. All records, both
methods pooled. (H2min is bounded by the observed entropy so H2′ stays in [0,1] — a fix
also applied to the main network script; it doesn't change the 0.29/0.43 values.)

**Outputs:** `genus_species_webs/<Genus>.png` (11 webs), `interactions_genus_h2_overview.png` (H2′ ranked across genera), `interactions_genus_h2.csv`, `interactions_genus_species_specialization.csv` (per species: breadth, top plant, % on it).

**Results:** a clean specialist→generalist gradient. **Perdita & Diadasia H2′ = 1.0** (each
species on its own plant — oligolectic), Anthophora 0.85, Dufourea 0.82, Ceratina 0.75,
Andrena 0.59, Halictus 0.50, Lasioglossum 0.44, Bombus 0.37, Agapostemon 0.26 — all p<0.05
— and **Habropoda 0.22 (p=0.51, n.s.)**, its two species interchangeable. Practical read: for
high-H2′ genera, species identity matters (a plant lost = a bee species lost); low-H2′
generalists (Bombus, Agapostemon) act as one interchangeable pollinator block.

## ✅ Phenology — flowering-plant & bee seasonal activity — `phenology`  (Q12 + bee extension)

**Script:** `scripts/analysis/phenology_activity.R`
**Run:** `Rscript scripts/analysis/phenology_activity.R` (needs `dplyr`, `stringr`, `ggplot2`, `ggridges`)

*When in the year is each taxon active?* Descriptive phenology from the records'
observation date — **not** climate modelling (`phenor`) or nesting-curve fitting
(CRAN `phenology`); those answer a different question and need inputs we don't have.

- **Ridgeline plots**: each taxon is a kernel density of its records across the year
  (day-of-year), stacked and **ordered by peak day**, filled on a **spring→fall
  gradient** (green = early, peach = late).
- **Flowering-plant** phenology per **plant genus** — this is BLOOM timing, not mere
  presence. A plant is around all year, so by survey protocol a plant is only logged
  when **in flower**; the flowering set is the **survey plant records** (7,148 of 9,243).
  The `flower_flowering` y/n column is filled on only ~68 rows, so it's used only to
  drop the 47 explicit `'no'` records, not as the primary filter. **Bee** phenology per
  **genus** and per **species** (both methods pooled) — unchanged.
- A taxon needs ≥ 10 records to get a ridge (bandwidth 15 days). Season caveat:
  interns ~Mar–Sep, beeple year-round, so winter tails partly reflect who was sampling.

**Outputs** (PNG + matching CSV each): `phenology_plant_genus.*` (75 flowering genera),
`phenology_bee_genus.*` (24 genera), `phenology_bee_species.*` (34 species). The plant
figure carries a red scope caption stating the flowering filter.

**Results (last run):** flowering plants sweep winter/spring bloomers (Agave, Marah, Lycium,
Lomatium) → summer/fall (Deinandra, Isocoma, Baccharis, Erigeron); **72 of 75** flowering
genera are significantly seasonal (Rayleigh p<0.05). Restricting to flowering dropped the
list from 89 to 75 genera — the trimmed ones were padded to the threshold by casual
"plant is present" photos, not bloom records. Bees run early-spring (Andrena, Habropoda) →
late-summer (Xenoglossa, Nomada, Megachile). Pairs with the top-plants forage calendar (Q3).

## ✅ Community diversity — `richness/diversity`  (Q8)

**Scripts:** `scripts/analysis/diversity_indices.R` (survey-only indices + composition)
and `scripts/analysis/spatial_richness_map.R` (all-records spatial map).
**Run:** `Rscript scripts/analysis/diversity_indices.R` (needs `dplyr`, `stringr`, `vegan`, `ggplot2`)
then `Rscript scripts/analysis/spatial_richness_map.R` (adds `sf`).

*How diverse is the bee community by transect and year, at genus vs species rank,
do the assemblages differ, and where in the park does richness concentrate?* Alpha
indices + rank-abundance + an NMDS/PERMANOVA composition test, following the vegan
methods in Stevens' *Primer of Ecology* (ch. 14), plus a whole-park richness map.

- **Scope, stated on every figure (red caption):** diversity indices and NMDS/PERMANOVA
  use **survey records only**, **both methods pooled**; the **rank-abundance** figure
  splits **lethal vs non-lethal** (that contrast is its point). Year comparisons are
  restricted to the **Mar–Sep** window. Specimens are all survey-collected already.
- **Indices** (`vegan`): richness, effective #species `exp(H)` (Hill q1), inverse
  Simpson (q2), Pielou evenness — per transect (species & genus) and per year.
- **Composition test:** PERMANOVA (`vegan::adonis2`, Bray–Curtis, transect × year sites) + NMDS.

- **Spatial richness map (`spatial_richness_map.R`, ALL records):** every georeferenced
  record snapped to a 75 m UTM grid; per-cell effort, genus richness, species richness,
  and — because raw richness tracks effort — an **effort-controlled rarefied** surface
  (cells with ≥20 records rarefied to 20). All-records scope is stated in each map's red caption.

**Outputs:** `diversity_by_transect.png/.csv`, `diversity_by_year.png/.csv`,
`diversity_rank_abundance.png`, `diversity_nmds_composition.png`,
`diversity_permanova.txt`, `diversity_statistics.docx`; plus maps
`map_species_richness.png`, `map_genus_richness.png`, `map_sampling_effort.png`,
`map_rarefied_richness.png`, and `spatial_richness_grid.csv` (per-cell table).

**Results (last run):** composition differs by **transect (R²=0.23, p=0.001)** and
**year (R²=0.50, p=0.001)** — year is the stronger axis (NMDS stress 0.12). UPMON & BST
carry the highest species diversity; OT the lowest and least even. At genus rank the
transects look much more alike, so most between-transect difference is within genera.
On the map, raw per-cell richness peaks in the most-sampled cells (25–31 species), but
the **rarefied** surface is much flatter (~8–10 species / 20 records) — i.e. most raw
spatial variation is a map of effort, so the rarefied map is the fair comparison.

**Q8 is now complete** — indices, composition test, and the spatial map are all built.

## ✅ Rarefaction — effort-controlled diversity — `richness/rarefaction`

**Scripts:** `scripts/analysis/rarefaction_vegan.R` and `scripts/analysis/rarefaction_inext.R`
**Run:** `Rscript scripts/analysis/rarefaction_vegan.R` (needs `vegan`, `ggplot2`); then
`rarefaction_inext.R` (needs `iNEXT` — one-time `install.packages("iNEXT")`, internet required).

*Fair diversity by controlling for sampling effort* — "if every group had been sampled the same,
how many species would each have?" Three cuts (survey-only, species rank, both methods pooled):
**by transect**, **by year** (Mar–Sep), **beeple vs intern**. See `rarefaction/README.md` for a
plain-language guide to the three methods and **which to trust** (short version: lead with iNEXT
**coverage-based**; use vegan rarefy-to-lowest as the simple cross-check).

**Outputs:** nested one folder per comparison — `by_transect/`, `by_year/`, `by_observer/`, `by_method/`
— each holding both ranks. vegan → `{species,genus}_vegan.csv` + `_vegan_curves.png` + `_vegan_bars.png`;
iNEXT → `{species,genus}_inext_size.png`, `_inext_coverage.png`, `_inext_asymptotic.csv`, `_inext_by_coverage.csv`, `_inext_by_size.csv`.

**Results (vegan, rarefy-to-lowest):** by transect (to 480 records) UPMON 34 ≈ BST 32 ≈ OT 30 ≈ TP 28 —
the raw gap shrinks and **OT is no longer the poorest** (its low raw count was mostly under-sampling);
by year (to 217) 2022 highest, 2024 lowest; by observer (to 1,560) **intern 49 > beeple 42** at equal
effort. (iNEXT adds Hill q1/q2 + coverage-based versions when run on a machine with internet.)
