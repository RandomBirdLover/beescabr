# beescabr

Native bee biodiversity pipeline for Cabrillo National Monument (CABR), comparing lethal (museum specimen) and non-lethal (iNaturalist photo) survey methods across CABR → Point Loma → San Diego County.

## Data rules

- **GBIF = regional reference context only.** GBIF records are never used as CABR survey records. CABR specimens are being deposited to SDNHM (via Pam Horsley) and are not yet in GBIF.
- **`data/` is gitignored** — no specimen, iNat, or personal data is on GitHub. The only exception is shapefiles under `data/spatial/`.
- **`data/outputs/` is generated.** Never edit output CSVs by hand — re-run the relevant script instead.
- **Buffers are generated in R**, not stored as shapefiles. Do not commit `Buffer_10m.*` or any derived shapefile.

## Naming conventions

### iNat and GBIF exports

```
inat_bees_sdcounty_YYYY-MM-DD.csv
inat_plants_sdcounty_YYYY-MM-DD.csv
gbif_bees_sdcounty_YYYY-MM-DD.csv
```

**Note on `inat_bees_sdcounty`:** as of 2026-06-22, this is one master export covering *all* bees (Anthophila) across the full San Diego County 25 Mile Buffer — see **iNat export instructions** below for why. It is not native-bee-only and not CABR- or Point Loma-specific; the Point Loma and CABR checklists are both derived from this same file via spatial subsetting (see **Pipeline overview**), not separate exports. (Filename kept as `inat_bees_sdcounty`, not `inat_native_bees_sdcounty`, to reflect that it's no longer native-only at the export stage.)

Date = download date, always YYYY-MM-DD. Drop the file directly into the correct subfolder — do not leave it in Downloads or rename it after the fact. Scripts auto-detect the newest file using `read_latest()`.

### Specimen file

```
CABR_bee_specimens_V{n}_{YYYY-MM-DD}.xlsx
```

All versions live in `data/cabr_surveys/lethal/`. The pipeline always reads the newest one. See **Specimen version management** below.

### Deposit and loan tracking files

```
deposit/CABR_bee_deposit_{taxon}_{recipient}.xlsx
loans/CABR_bee_loan_{taxon}_{recipient}.xlsx
```

## Specimen version management

All versions of the specimen Excel file live together in `data/cabr_surveys/lethal/`. The R pipeline uses `read_latest()` to automatically pick up the newest version every time — no manual archiving or file moving required.

**When you update the specimen file:**
1. Open the current version in Excel
2. Make your changes
3. **Save As** → `CABR_bee_specimens_V{n+1}_{YYYY-MM-DD}.xlsx` in the same `lethal/` folder
4. Add a row to `SPECIMEN_CHANGELOG.md` describing what changed
5. Commit and push `SPECIMEN_CHANGELOG.md`

**Do NOT** delete or overwrite old version files. **Do NOT** rename the file without updating the version number and date.

**Version bump rule:** Any deletion or structural change (column added, removed, renamed; values corrected or reclassified) = new version. Adding new rows does not require a version bump but should still be noted in the changelog.

## iNat export instructions

**As of 2026-06-22, this is one master export per refresh cycle** — not a per-checklist or per-tier export. The single export below covers all of San Diego County and is reused as the shared source for the county-wide, Point Loma, and CABR checklists (see **Pipeline overview**). There is no need to re-export separately for each geographic tier.

Go to **inaturalist.org/observations/export** and apply these settings:

### Filters

| Field | Value |
|-------|-------|
| Taxon | `Anthophila` (all bees) |
| Without taxon | *Apis mellifera* (Western Honey Bee) — see note below |
| Place | **San Diego County 25 Mile Buffer** — not plain "San Diego County" (see note below) |
| Quality grade | Any |
| Geoprivacy | Include obscured |
| Captive/Cultivated | Unchecked (exclude) |

**Why Quality grade = Any, not Research Grade only:** iNat's "Research Grade" requires community identification to species level. Most bees in photos can only be reliably identified to genus, not species — restricting to Research Grade would silently drop a large share of genuinely usable genus-level observations. "Any" is intentional here, not an oversight.

**Why exclude *Apis mellifera*:** honey bee observations are extremely numerous on iNat and were bloating export size/processing time without adding value for this project's native/wild-bee-focused analysis. This exclusion happens **at export time**, not downstream in code — if a future question specifically needs honey bee data, that requires a separate targeted export; it will not be present in the master file. Do not remove this exclusion without a specific reason, since doing so will substantially increase file size.

**Why "25 Mile Buffer" and not plain county:** this is a deliberate choice, consistent with how `cabr_survey_box` and the hand-edited `point_loma_boundary`/`sd_county_boundary` shapefiles work elsewhere in this project — survey-relevant observations near the county edge (e.g. close to CABR/Point Loma) shouldn't be cut off just because they fall slightly outside the county's literal administrative polygon. Spatial filtering to the actual boundaries of interest happens downstream via `spatial_utils.R`, not at export time.

For plants, taxon `Plantae` is exported separately (no honey-bee-style exclusion needed); SD County 25 Mile Buffer should still be used as the Place for consistency.

### Columns — uncheck to reduce file size

- Observation fields
- Description
- Tag list
- Sounds

### Required columns

`id`, `observed_on`, `quality_grade`, `taxon_id`, `scientific_name`, `common_name`, `taxon_rank`, `latitude`, `longitude`, `positional_accuracy`, `geoprivacy`, `captive_cultivated`, `user_login`, `place_guess`

### After downloading

Rename to the convention above and drop into the correct subfolder. Do not keep the default iNat filename.

## Pipeline overview

`native_bee_data_analysis.Rmd` is the orchestrator — it sources everything below in order, so in practice you just run the Rmd chunk by chunk. Listed individually here for reference:

```
1. native_bee_checklist.R          reads ONE master iNat export (inat_bees_sdcounty, all of SD
                                   County 25mi buffer, Apis mellifera excluded — see iNat export
                                   instructions) → builds SD County bee checklist
                                   (hits iNat API ~430 calls, ~3-4 min)
                                   → writes data/outputs/SD_inat_bee_checklist.csv
                                   (only re-run if that file doesn't already exist)

   ↳ Point Loma and CABR checklists are spatial SUBSETS of the same SD County
     checklist above (filtered by point_loma_boundary / cabr_survey_box from
     spatial_utils.R), not separate iNat exports. See TODO: checklist architecture.

2. native_bee_reference_table.R    reads checklist → builds key_full reference table
                                   → writes data/outputs/SD_bee_reference_table.csv

3. clean_specimens.R               reads newest CABR_bee_specimens_V{n} → cleans lethal data
                                   → writes data/outputs/CABR_bee_specimens_clean.csv

4. clean_nonlethal_inat.R          reads intern + beeple iNat exports → cleans non-lethal data
                                   → writes data/outputs/CABR_nonlethal_inat_clean.csv
                                   (reports "no data found yet" until those folders are populated)
                                   (kept strictly separate by method — intern vs. beeple — never
                                   merged; see TODO: checklist architecture)

5. spatial_utils.R                 reads boundary shapefiles (CABR, Point Loma, SD County) +
                                   CABR_transects.shp → generates buffer_10m in memory; also
                                   provides cabr_survey_box / point_loma_boundary used to spatially
                                   subset the master checklist in step 1 above

6. native_bee_data_analysis.Rmd    sources 1–5 above, then does the actual richness/method comparison
```

`utils.R` (shared `read_latest()` and `require_columns()`) is sourced by every script above — not a standalone step.

## Complex rank handling

iNaturalist uses a taxonomic rank called **Complex** for cryptic species groups that cannot be reliably distinguished from photos (e.g. *Andrena osmioides*, *Diadasia australis*). The pipeline handles these as follows:

- Each taxon has a `taxon_complex_name` column (complex name) and `taxon_complex_id` column in the checklist
- Complexes are **not excluded** from richness counts — each unique `taxon_id` counts as one taxon
- `taxon_complex_name` is the join key for matching iNat photo observations against museum specimens
- Exact `taxon_id` match is preferred; complex-level matches are flagged separately
- `taxon_complex_name` was added to the specimen sheet in V9 (populated via Genus+Species match against the checklist — see `SPECIMEN_CHANGELOG.md`)

## Spatial analysis

Transect buffers are generated in R via `spatial_utils.R`. Default = 10m. To change:

```r
buffer_dist_m <- 5  # change this one line in spatial_utils.R
```

CRS: EPSG:26946 (NAD83 / California zone 6, meters) — no reprojection needed.

### Boundary layers (added 2026-06-22)

Boundary shapefiles live in `data/spatial/boundaries/`, each in its own subfolder:

| File | Location | Source | Notes |
|------|----------|--------|-------|
| `cabr_boundary.shp` | `boundaries/cabr/` | NPS Land Resources Division (UNIT_CODE = CABR) | Official monument boundary. 160.4 acres, matches NPS-published figure (~160 acres). Used as a provenance label only — see below, not a filter. |
| `cabr_survey_box.shp` | `boundaries/cabr/` | Hand-drawn in ArcGIS Pro | The actual CABR-tier inclusion geometry — see below. Lives alongside `cabr_boundary.shp`, not in its own subfolder. |
| `point_loma_boundary.shp` | `boundaries/point_loma/` | City of San Diego "PENINSULA" community plan district, hand-edited | Custom working boundary — see gap-resolution history below. Not an authoritative city/NPS polygon. |
| `sd_county_boundary.shp` | `boundaries/san_diego_county/` | County of San Diego Open Data Portal, hand-edited | Custom working boundary, expanded by hand from the raw export — not the raw export itself. Treat as project-specific, not an authoritative county polygon. |

All are reprojected to EPSG:26946 in `spatial_utils.R` on load, since none of the source files arrive in that CRS natively.

#### CABR survey area vs. official NPS boundary

Per Taro (2026-06-22): the BST transect begins on Navy-owned land south of the official CABR (NPS) boundary, but this area has historically been surveyed as part of CABR and should be counted as such — regardless of official ownership.

This is implemented via `cabr_survey_box`: a **hand-drawn polygon** (not a formula-based buffer) built in ArcGIS Pro to extend past `cabr_boundary` on the north, south, *and* southeast — generous on every side, since a uniform south-only buffer couldn't capture the irregular extension this required. `cabr_survey_box`, not `cabr_boundary`, is the actual inclusion geometry for CABR-tier spatial joins.

`cabr_boundary` (the official NPS polygon) is retained purely as a *provenance label* — every point gets classified as `inside_nps_boundary == TRUE/FALSE`, but this label never excludes a point from being counted as CABR. This is intentionally a label, not a filter. Being inside `cabr_survey_box` doesn't by itself mean "CABR" either — points still get classified downstream (inside NPS boundary, Navy-but-CABR, or something else/Point Loma); the box's job is just to be generous enough that nothing relevant gets excluded before that classification happens.

`spatial_utils.R` runs `st_contains(cabr_survey_box, cabr_boundary)` on every run to confirm the box still fully contains the official boundary, rather than assuming it.

#### Point Loma boundary: gap resolution history

`point_loma_boundary` started from the City of San Diego's "PENINSULA" community plan district, but didn't fully cover `cabr_boundary` — manual extension in ArcGIS was required over two gap areas (a northern tongue and a southern/BST-transect-spur area).

Containment vs. `cabr_boundary` was tracked through several attempts:

1. Original "PENINSULA" district: **4.69 acre gap**
2. Automated Union+Dissolve attempt: **5.69 acre gap** — this made the gap *worse*, not better, and was abandoned
3. Careful manual ArcGIS edit: **0.0105 acre gap** (~460 sq ft) — a genuine seam/precision artifact at this point, not a real missing area
4. **5m buffer applied on load** (`POINT_LOMA_SEAM_BUFFER_M` in `spatial_utils.R`): gap fully resolved

`spatial_utils.R` runs `st_contains(point_loma_boundary, cabr_boundary)` on every run to re-verify this rather than assuming it. If it ever fails, the script computes the exact gap via `st_difference()` and writes it to `boundaries/DIAGNOSTIC_cabr_gap.shp` (gitignored) for inspection in ArcGIS/QGIS.

**Lesson learned:** automated Union+Dissolve is not a reliable fix for boundary gaps in this project — manual ArcGIS editing succeeded where the automated approach failed.
