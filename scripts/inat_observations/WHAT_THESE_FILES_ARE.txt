WHAT THIS FOLDER IS
===================

Everything that talks to iNaturalist, and everything that cleans what comes back.

Writes to data/inat_observations/.


THE LAYERS, BOTTOM TO TOP
=========================

  engine/api/        HTTP, rate limiting, and turning the JSON into rows.
  engine/db/         The DuckDB cache: connections, tables, compaction.
  engine/pipelines/  Ingest. THE ONLY CODE THAT CALLS THE OBSERVATIONS API.
  clean/             Turning cached records into the cleaned tables.
  review/            Writes the review files a person looks at.

At the top sit the two tools you run rather than the pipeline: authorize_inat.R
(one-time API authorisation) and build_field_id_map.R (refreshes the iNaturalist
observation-field ids the project reads).

Dependencies point DOWN that list and never up. If a cleaning script needs
something from the API, it goes through the cache. It does not make its own
request.


ONE FETCH ENTRYPOINT
====================

    engine/pipelines/ingest_inat.R

That is the only place observations are downloaded. Everything else reads the
DuckDB cache. This is deliberate: one place to reason about rate limits, one
place that can go wrong, and an analysis run that never touches the network.


THE CLEANING SCRIPTS
====================

  clean/inat_bee_clean.R    the bee observations   -> cabr_inat_bee_clean_generated.csv
  clean/inat_plant_clean.R  the plant observations -> cabr_inat_plant_clean_generated.csv
  clean/bee_forage.R        which bee was on which plant
  build_field_id_map.R      the iNat observation-field ids the project uses

review/ writes the QC files: probable misidentifications, records outside the
park, tags that matched no survey. Those are questions for a person, not errors.

inat_bee_clean.R does not decide which records are surveys. The brain did that
(scripts/project_info/, see THE RULES in its WHAT_THESE_FILES_ARE.txt): the tag
is the evidence, a surveyor's transect for the day is the majority tag, and the
50 m rescue only pulls untagged records in, never tagged ones out. This script
looks that answer up by obs_id and adds taxonomy, coordinates and the crosswalk
annotations.

Its last step drops photos of collected specimens: any record whose Specimen?
obs-field is yes. The field-name spellings come from the crosswalk's specimen?
row (inat_field_variants), so a new spelling is a crosswalk edit. The dropped
rows go to data/inat_observations/review/qc_review_inat_specimen_photos_generated.csv.
The specimen column stays in the clean table (blank reads as no) so a field
corrected on iNaturalist takes effect on the next run. A specimen photo nobody
marked cannot be told from a live bee and stays in.


TESTING NETWORK CODE
====================

No test ever hits the real API. Every function that makes a request takes a
request_fn argument, and the tests pass a fake. If you add one, keep that shape.
