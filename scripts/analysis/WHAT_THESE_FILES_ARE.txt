WHAT THIS FOLDER IS
===================

One script per figure or table. Together they produce everything in
data/analysis/.

Writes to data/analysis/<year>_generated/ -- never edit the output, edit the
script.

The subfolders mirror the topic folders in data/analysis/, so a script sits in
the same folder its output does:

    coverage/           how much was sampled, and what was missed
    richness/           how many kinds, and the curves behind that number
    phenology/          when bees and plants are active
    interactions/       which bees visit which plants
    method_comparison/  netting versus photographing
    reference/          field guide, maps, explorers, NPS summary tables
    shared/             helpers. Sourced by other scripts; produce nothing.

WHERE A NEW FILE GOES, IN ONE RULE
----------------------------------

    a topic folder     it produces that topic's output
    shared/            it produces NOTHING -- other scripts source it for its
                       functions. Sourcing a file in here must never write
                       anything to disk. Any write call lives inside a function
                       body, so nothing happens until a caller asks for it.
    this level         it produces output that belongs to no single topic

That is why findings_summaries.R and render_palette.R sit at the top rather than
in shared/: both of them RUN. findings_summaries.R writes a findings file into
every topic folder plus the index a reader starts from; render_palette.R draws
the theme swatch into dev-docs/. Filing either under shared/ would make the
folder stop meaning anything -- you would have to open a file to find out
whether sourcing it has side effects.


SOME OF THESE PRODUCE WEB PAGES, AND THAT IS FINE
=================================================

About ten scripts here write .html as well as .png and .csv -- the explorers,
the field guide, the bounty tables, the transect map. They still belong here,
not in scripts/website/.

A script that computes a page is an analysis. It writes into
data/analysis/<topic>/website/, beside the CSV of the same numbers. Afterwards
scripts/website/publish_pages.R copies those pages into docs/ and wraps them in
the site -- that folder is the only thing that writes into docs/.

Rule of thumb: if you are changing what a page SAYS, the fix is here, in the
script that computed it. If you are changing how the SITE is assembled, the fix
is in scripts/website/.


THE RULE THAT WILL BITE YOU
===========================

run_all_analysis_pipeline.R runs EVERY .R file in this folder, automatically.
Add a script here and it runs on the next pipeline run, with no registration
step.

That is convenient for an analysis and wrong for a HELPER. A file that only
defines functions for another script to use belongs in shared/, AND must be
listed in .modules in
run_all_analysis_pipeline.R, or the runner will execute it as though it drew a
figure. tests/testthat/test-analysis-modules.R checks the two agree, and fails
if they drift -- which they already had, by three files, before the check
existed.


THE SHARED PIECES
=================

  theme_beescabr.R      Colors, fonts, captions. THE ONLY PLACE A COLOR IS
                        DEFINED. Never write a hex code into an analysis
                        script; add a token here and reference it.
  utils_analysis.R      Shared helpers for reading the cleaned tables.
  rarefaction_names.R   Output names + the fair windows for the method and
                        observer comparisons.
  folder_readmes.R      Writes the notes that explain data/analysis/.
  findings_summaries.R  Runs LAST. Writes one findings file per analysis plus
                        findings_index.csv, the index a reader starts from.


WHAT AN ANALYSIS SCRIPT LOOKS LIKE
==================================

Read the cleaned tables, compute, then write a figure and the table behind it
into the same folder. Every figure carries a caption saying its scope, its
method and where the data came from -- scope_cap() builds it, and a figure that
ran a statistical test also passes bee_test().

If you are adding one, copy the shape of a short existing script rather than
starting from scratch: coverage_offtransect.R is a readable example.
